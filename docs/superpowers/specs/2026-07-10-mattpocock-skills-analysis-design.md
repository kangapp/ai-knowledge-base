# mattpocock/skills 专题分析设计

## 目标

在 `docs/analysis/mattpocock-skills/` 新增一个与现有架构分析项目风格一致的专题，基于 `mattpocock/skills` 仓库源码，说明技能的安装与配置方式、调用模型、完整使用工作流、产物交接关系，以及适合读者理解和检索的内容结构。

分析固定到上游 `main` 分支提交 `391a2701dd948f94f56a39f7533f8eea9a859c87`（2026-07-10），避免把后续变化混入本次结论。正文同时提供仓库主页和关键源码文件链接，方便读者检查原始证据。

## 设计选择

采用“工作流主导、技能目录辅助”的双层信息架构，不直接把上游目录树当作主要导航。

上游的 `engineering`、`productivity`、`misc`、`personal`、`in-progress`、`deprecated` 主要表达维护与发布状态；读者的首要问题则是“我现在处于什么情境，应该从哪个技能开始”。专题先按情境和工作流组织，再用技能目录提供完整查阅入口。

## 输出结构

```text
docs/analysis/mattpocock-skills/
├── skills-analysis.md
├── skills-workflow-diagram.md
└── index.html
```

### `skills-analysis.md`

长篇中文分析正文，包含：

1. 研究范围、快照和结论摘要。
2. 仓库定位与核心哲学：小技能、可组合、人工保留控制权、工程反馈环。
3. 安装与首次配置：`npx skills@latest add mattpocock/skills`、选择技能、运行 `/setup-matt-pocock-skills`、生成仓库级配置。
4. 两种调用模式：用户主动调用与模型自动调用，以及二者的依赖约束。
5. 主工作流：想法澄清、可选原型、Spec、Tickets、实现、TDD、双轴审查和提交。
6. 情境入口：Bug、外部 Issues/PR、超大且模糊的工作、架构维护、研究与跨会话交接。
7. 产物流：`docs/agents/*`、`CONTEXT.md`、ADR、Spec、Tickets、测试、Review、handoff 和研究文档。
8. 正式技能目录：为插件清单中的 21 个技能列出调用者、输入、输出、依赖、流程位置和适用边界。
9. 非正式技能区：`misc`、`personal`、`in-progress`、`deprecated`，只解释其状态，不把它们列为默认推荐。
10. 设计评价：优势、使用成本、隐含假设、潜在风险和当前仓库一致性观察。
11. 对本项目的借鉴建议：只提可落地的结构与流程启示，不直接修改本项目的 Agent 规则。
12. 一手资料索引。

### `skills-workflow-diagram.md`

集中放置 Mermaid 图，避免正文被大图打断：

- 情境路由图：用户当前问题到首个技能。
- 主流程图：`setup → grill-with-docs → prototype? → to-spec → to-tickets → implement → tdd → code-review`。
- 技能调用关系图：用户调用技能、模型调用技能和组合依赖。
- 产物交接图：配置、领域文档、Spec、Tickets、代码与审查结果的流动。
- 状态分层图：正式发布、非推广、开发中和废弃技能。

### `index.html`

制作无外部构建依赖的自包含中文单页，延续现有 `architecture/index.html` 的视觉语言：固定宽度信息海报、编号分区、蓝绿琥珀状态色、卡片和右侧详情抽屉。

页面按以下顺序展示：

1. 项目定位与快照。
2. “你现在遇到什么”情境入口。
3. 端到端主工作流。
4. 调用模型与组合规则。
5. 产物交接链。
6. 正式技能矩阵。
7. 非正式技能状态区。
8. 关键判断、限制与本项目借鉴。

点击情境或技能卡片后，详情抽屉展示用途、调用方式、输入、输出、前置条件、上一步、下一步和源码链接。页面不复制完整 `SKILL.md`，只呈现经过归纳的使用决策和流程关系。

## 内容边界

- 只分析公开仓库中可核实的内容，不推测作者未写明的意图。
- 事实和评价分开表达；推断明确标注为分析判断。
- 正式技能以 `.claude-plugin/plugin.json` 为准，目录中的草稿、个人和废弃技能不计入正式数量。
- 记录“promoted 目录有 22 个技能目录、插件清单暴露 21 个”的快照差异，并指出 `resolving-merge-conflicts` 未进入插件清单；不把它武断定性为缺陷。
- 不安装或运行上游技能，不改本项目现有工作流、代码和站点构建逻辑。
- 不新增依赖，不引用二手评测或营销文章。

## 验证标准

1. 三个文件均存在，目录名可被现有 `docs/analysis/*/index.html` 发布规则发现。
2. Markdown 标题、表格、代码块和 Mermaid 围栏完整，无占位符。
3. HTML 的标题可被 `_html_title()` 提取，移动端可阅读，卡片与详情抽屉可通过鼠标和键盘操作。
4. 正式技能数量、用户/模型调用数量与插件清单一致：21 个，其中 13 个用户调用、8 个模型调用。
5. 所有关键事实能追溯到 README、插件清单、`ask-matt`、调用规则或相应 `SKILL.md`。
6. 运行现有站点构建相关测试，确认新目录不破坏分析页发布。

## 不在本次范围内

- 修改站点分析列表模板或新增搜索、筛选 API。
- 将上游技能安装到本项目或改写本项目 `AGENTS.md`。
- 对每个草稿、个人或废弃技能做与正式技能同等深度的逐项分析。
- 跟踪上游提交后的持续同步机制。
