⑧关键判断与本项目借鉴

对上游体系的判断

  • 稳定产物让小技能可组合，也让失败位置可见；代价是用户必须理解调用边界。
  • Setup、grilling、Spec、Tickets、triage 与架构选择都设人工决策门，提升控制权但降低无人值守程度。
  • 前期保留上下文、实施逐票清空，是决策连续性与实现专注度之间的成熟分段。
  • Issue Tracker 配置是关键可移植 seam；真实平台能力差异仍会影响可靠性。
  • TDD、诊断和 review 以可执行证据优先；最难且最有价值的是选择代表用户行为的 public seam。

对 AI Knowledge Base 的结构借鉴

  • 在模块目录之外补充“采集异常、分析质量、Prompt 回归、API 展示、部署故障”等情境入口。
  • 为采集结果、分析结果、Reviewer 评分、数据库记录与静态站输出明确生产者、消费者和生命周期。
  • 用单独清单区分正式、试验中、环境特定与已弃用能力，不让目录位置替代发布状态。
  • 保留来源仓库、完整 SHA、研究日期和精确文件链接，面对上游变化时显式更新快照。
  • 保持 Collector → LangGraph → Reviewer → 入库 → 静态站/API 主链简洁，把例外入口单独表达并允许回流。

这些借鉴用于补充导航与产物说明，不替换本项目现有 AGENTS.md 的权威约束。
