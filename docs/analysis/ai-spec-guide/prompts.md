# 进阶 Prompt 工具箱

首次使用从[开始共创](README.md)复制启动提示词。下面的模板用于追加当前阶段的要求；替换花括号，一次选用需要的模板。已确认决定继续沿用，不重复询问。

<details>
<summary>P01 · 对齐目标与材料</summary>
<pre class="starter-prompt"><code>我们要共创《{名称}》，原始想法是 {内容}。
材料与约束：{内容}；文档用于 {需求设计 / 实现设计 / 业务逻辑 / 现状说明}。
先简短复述目标、读者、范围与成功标准，区分事实、假设、建议和待定项。
代码现状与旧文档不自动作为新设计；来源冲突时列出差异和影响。
只提出最影响方向的一个问题，给出具体场景、选项和推荐前提。
本轮不展开长篇正文，不把沉默当成确认。</code></pre>
<p>检查：是否准确复述了想法，是否把 AI 的建议混入目标？</p>
</details>

<details>
<summary>P02 · 形成需求全景</summary>
<pre class="starter-prompt"><code>目标与已有决定：{内容}；当前材料：{内容}。
请生成简短、完整的需求全景：问题、范围、核心场景、主流程、
关键规则、失败与边界、验收方式、未知项及影响。
用主流程图和短规则表帮助我判断方向；大纲不能代替行为共识。
待定项明确标记，不为完整性编造规则或指标。
指出最需要确认的方向问题；经确认后再增加实现细节。</code></pre>
<p>检查：不读后续章节，能否判断整个需求是否符合意图？</p>
</details>

<details>
<summary>P03 · 用场景澄清一个决定</summary>
<pre class="starter-prompt"><code>当前全景与规则：{内容}；本轮问题：{内容}。
用相同前提比较 2–3 个选项，展示操作与结果、失败或反例、主要影响。
推荐项注明适用前提，允许我自定义答案或保留问题。
能查证的内容先查证；我的明确答案写入规则表并同步全景。
若答案改变目标或范围，先展示新的全景供我确认。</code></pre>
<p>检查：能否根据具体结果作选择，而不只是比较抽象名称？</p>
</details>

<details>
<summary>P04 · 维护 HTML 审阅页面</summary>
<pre class="starter-prompt"><code>当前全景、完整草稿、规则与待定项：{内容}。
维护同一个 HTML 审阅入口，沿用既有样式和布局：
整体概览 → 本轮问题与场景 → 完整草稿 → 修订记录。
默认突出短结论和本轮变化，长解释、来源按需展开；全文始终可访问。
交互演示只使用已有规则，标明候选、已确认和未定义结果。
没有实际提交功能时，选择只供预览，并支持将反馈复制回对话；
不能声称按钮点击已经提交给 AI 或保存为需求。
实际检查桌面、窄屏和键盘操作；不支持 HTML 时提供短文本与表格并说明。</code></pre>
<p>检查：演示是否准确，是否把临时预览冒充已确认决定？</p>
</details>

<details>
<summary>P05 · 按场景完善整份草稿</summary>
<pre class="starter-prompt"><code>当前完整草稿、已确认全景与规则：{内容}。
本轮完善场景：{条件、操作与结果}。
同步完善对应正文、必要设计、图表和验收，不仅生成一个孤立章节。
为核心规则保留稳定编号，记录对应位置与确认状态。
新增取舍标为待定，已确认无关内容继续沿用。
默认展示本轮修改摘要和待决定问题，保留当前完整草稿入口与状态。</code></pre>
<p>检查：全景、详细规则、设计和验收是否描述同一个行为？</p>
</details>

<details>
<summary>P06 · 改善表达与文内自洽</summary>
<pre class="starter-prompt"><code>文档与目标读者：{内容}；必须保留的事实与规则：{内容}。
借鉴 ASD-STE100 的简明表达原则：短句、主动表达、一句一个主要意思、
一段一个主题、同一概念同一术语。中文不宣称严格符合英语规范。
写明条件、执行者、动作、结果与例外，保留必要解释。
外部链接只提供来源与背景，必要定义、结论和约束写入本篇。
忽略外部链接后检查能否解释核心场景；缺事实时标为待核实，不编造。
同类标题、规则、表格、图注和状态沿用统一格式。</code></pre>
<p>检查：变短后是否仍然准确，读者是否还必须跳转才能知道核心规则？</p>
</details>

<details>
<summary>P07 · 根据规则生成设计、图表与验收</summary>
<pre class="starter-prompt"><code>已确认规则与适用范围：{编号及正文}；现状材料：{内容}。
先写明本篇所需的规则摘要与约束，再附来源。
按实际需要形成最小设计、流程图 / 状态图 / 时序图 / 决策表及验收案例。
每项设计、图表与验收关联规则编号，不新增未经确认的行为。
拟议结构标为建议；图注说明省略范围，实际渲染检查文字与连线。
验收包含前提、操作、预期结果与验证方式，统一标为待执行。
无法确定的预期结果列为缺口，不替我作业务决定。</code></pre>
<p>检查：有没有无依据的新机制，图和验收是否遗漏失败及边界？</p>
</details>

<details>
<summary>P08 · 修改规则并同步全文</summary>
<pre class="starter-prompt"><code>当前完整基线：{版本与内容}。
变化：{旧约定 → 新约定及理由}；确认状态：{已确认 / 待讨论提议}。
提议未确认时保留基线，只展示候选和影响。
明确决定后按“记录决定 → 列出影响 → 同步修订 → 全文核对 → 更新版本”执行。
核对正文、定义、示例、图表、设计与验收；关联表不能代替语义检查。
只修改必要位置，保留无关内容和展示样式。
新取舍未解决时标为正在修订，保留上一份完整基线，不交付混合版本。
报告实际修订位置、已执行检查、待完成项和当前完整草稿入口。</code></pre>
<p>检查：是否完整覆盖影响，是否仍有旧规则被当作当前约定？</p>
</details>

<details>
<summary>P09 · 审校定稿</summary>
<pre class="starter-prompt"><code>目标、范围与决定：{内容}；完整文档和页面：{内容}。
仅根据当前文档解释正常、失败、边界和代表性反例。
检查需求覆盖、文内自洽、来源、规则冲突、图文设计与验收一致性、
旧规则残留、未决事项和实际排版展示。
问题注明位置、证据、影响和最小修正；常规修正直接完成，关键取舍交给我。
检查未执行项据实标记，不给无依据评分，不声称通过尚未执行的测试。
阻塞项解决并核对全文后，输出完整交付版本与检查记录。</code></pre>
<p>检查：同一个案例是否存在两种合理解释？检查结论是否有实际依据？</p>
</details>

<details>
<summary>P10 · 从已有长文或新对话接续</summary>
<pre class="starter-prompt"><code>当前文档、页面和必要讨论：{内容}。
提取目标与范围、简短全景、完整基线入口、当前版本和状态、
已确认规则与依据、关联位置、候选变化、待定事项及影响、检查与下一步。
历史提议不写成当前决定，历史规则与当前规则清楚区分。
已有长文先用代表性场景核对意图，再修订差异，不从头逐节重写。
接续摘要应足以定位完整状态，不依赖模型记住整个聊天，也不复制整段历史。</code></pre>
<p>检查：下一轮能否知道什么已确认、什么正在修订、从哪里继续？</p>
</details>

## 常见低效提示与修正

| 提示 | 主要问题 | 修正方向 |
| --- | --- | --- |
| 按目录一节一节写 | 局部合理但整体可能偏离 | 先确认全景，再按场景完善全文 |
| 越详细越好 | 阅读成本与范围失控 | 短结论先展示，细节按需展开 |
| 遵循项目其他文档即可 | 本篇缺少必要规则 | 写明采用的结论与边界，再附来源 |
| 只改这一句话 | 关联设计与验收可能遗留 | 先查影响，同步修订并核对全文 |
| 全文重新生成一次 | 无关内容与版式容易漂移 | 沿用基线，只改受影响位置 |
| 做成漂亮网页 | 外观可能掩盖行为缺口 | 要求规则一致、预览边界与实际展示检查 |

观察实际问题调整提示：方向偏了就补全景与场景，阅读吃力就缩短默认展示，修改遗漏就补关联位置和全文检查。表达更流畅不代表事实更准确。
