# 收藏功能案例：从全景到一次完整修订

原始想法：“给个人知识库加收藏功能，方便以后看。”下面演示如何先确认整体行为，再完善文档，以及修改一项规则后如何维护全文。

> 全部问答、规则、接口与数据均为教学示例。“已确认”仅指模拟对话内的约定，不代表本仓库现状或真实用户授权。所有验收案例均待执行。

## 1. 先对齐目标

AI 复述：帮助个人用户再次找到感兴趣的文章，最终形成供研发与测试使用的 Spec。先澄清收藏是否需要跨浏览器保留，因为答案会改变存储方案和使用方式。

示例用户选择：服务器保存，刷新或重新进入时读取状态。本期只做收藏、取消和收藏列表。

## 2. 展示完整全景

| 内容 | 初步全景 |
| --- | --- |
| 目标 | 再次找到已收藏文章 |
| 范围 | 个人收藏、取消、列表、状态恢复 |
| 主流程 | 选择文章 → 提交收藏 → 保存成功 → 更新按钮和列表 |
| 失败 | 确认保存失败时保留原状态；结果未知时重新读取 |
| 关键约束 | 同一文章最多一条收藏关系；取消不删除文章 |
| 验收 | 收藏后刷新仍保留，取消后文章仍存在，失败和未知结果可区分 |
| 待定 | 重复收藏是否更新时间，排序规则，文章删除后的处理 |

示例用户认可整体方向。非目标包括多用户、分组、标签、批量操作、原文快照和跨窗口实时同步；单个界面按顺序提交修改，本例不定义跨客户端并发冲突策略。

这里先确认完整逻辑，不急于生成数据库字段和接口文档。

## 3. 用场景作出决定

假设当前列表为 B（10:00）、A（09:00），11:00 再次收藏 A：

| 选择 | 可见结果 | 需要考虑什么 |
| --- | --- | --- |
| 保留原时间 | B 仍在 A 前面 | 顺序稳定，请求重试不改变时间 |
| 更新为当前时间 | A 移到 B 前面 | 新操作与同一操作的重试是否需要区分？ |

示例用户选择保留原时间，并继续确认：列表按收藏时间倒序，同时间按文章 ID 倒序；取消后重新收藏采用新时间；文章删除时同步清理收藏关系。

AI 将这些答案写入全景与规则表，再开始补充详细内容。

## 4. 完善完整基线 v0.1

本例 v0.1 是模拟用户已确认的行为与设计基线，未实施、未执行验收。后面的候选变化不会覆盖它。

**必要定义**：收藏关系表示一篇文章进入个人收藏清单，包含文章 ID 与收藏时间。收藏列表仅展示存在收藏关系的文章。取消收藏删除关系，文章本身保留。

| 编号 | v0.1 的已确认规则 |
| --- | --- |
| R-01 | 文章存在时可以收藏；同一文章最多一条收藏关系 |
| R-02 | 保存成功后更新按钮；刷新或重新进入时读取服务器状态 |
| R-03 | 取消成功后删除关系，在收藏列表移除该项；文章保留 |
| R-04 | 确认保存失败时保留原已确认状态，提示失败并提供重试入口 |
| R-05 | 重复收藏保留原时间；重复取消按成功处理；取消后重新收藏采用新时间 |
| R-06 | 按收藏时间倒序，时间相同按文章 ID 倒序 |
| R-07 | 文章删除时同步清理收藏关系，不保存原文快照 |
| R-08 | 请求结果未知时提示“结果待确认”，重新读取服务器状态；读取失败时保持待确认并提供重试读取入口 |
| R-09 | 空列表显示空状态与返回文章列表入口；读取失败显示错误与重试，不能显示为空列表 |

## 5. 修改提议：再次收藏应置顶

模拟用户提出新想法后，AI 先记录为候选，不直接覆盖 v0.1。该变化会改变时间写入和排序，还可能让网络重试再次更新收藏时间。

**AI 的关键问题**：一次收藏已保存但响应丢失，重试时是否仍沿用第一次保存时间？

| 选项 | 影响 |
| --- | --- |
| A．每次收到请求都更新时间 | 机制简单，但网络重试也会改变排序 |
| B．新操作更新时间，同一操作重试保留时间 | 需要区分操作身份，保证重试得到相同结果 |

本例模拟用户明确选择 A：每次成功执行收藏请求都采用服务器当前时间，接受网络重试也会再次更新收藏时间。这是明确的业务取舍，不由 AI 擅自决定。选 B 则需要先澄清操作身份与重试约束，再增加相应设计。

## 6. 同步修订完整草稿 v0.2

| 受影响位置 | v0.2 的对应修订 |
| --- | --- |
| 全景与 R-05 | 重复收藏更新时间；重复取消和取消后重新收藏的规则不变 |
| 收藏时间约定与 I-01 | 每次成功执行收藏请求都写入服务器当前时间；收藏状态不反转，但不再承诺时间保持不变 |
| 排序说明与演示 | R-06 的排序依据不变；A 于 11:00 再次收藏后，A 排在 B 前面 |
| G-01 | 已收藏到已收藏的标签改为“重复收藏成功，更新时间” |
| AC-02 | 关系数不变、时间变为 11:00、A 排在 B 前面 |
| AC-09 | 保存成功但响应丢失后，11:01 重试成功，时间更新为 11:01，并按该时间排序 |
| 其他案例 | 核对重新收藏、失败、删除、同时间排序仍成立 |

原有 v0.1 保留为历史基线。下面的 v0.2 包含完整必要规则、设计与验收，不只列变化；真实共创时使用同一个当前文档入口，历史版本另行保留。
