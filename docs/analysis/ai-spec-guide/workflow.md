# 五步流程详解

先确认整体行为，再按场景加深内容。AI 维护一份完整草稿；每轮只请你判断最影响方向的问题。你可以选择、自定义答案或保留问题，沉默不代表确认。

## 1. 对齐目标

AI 读取想法与材料，用简短摘要复述：谁遇到什么问题，文档供谁使用，本期解决到哪里，怎样判断完成。区分已确认事实、假设、设计建议与待定问题。

材料用于理解背景。代码描述现状，旧文档记录已有约定，都不能自动替代你对新需求的选择。来源冲突时，AI 列出差异、适用范围和影响。

**产物**：任务摘要与最影响方向的问题。**继续条件**：你认可目标、范围和用途；有分歧的部分先澄清，不展开依赖该答案的设计。

## 2. 确认全景

AI 提供一份简短、完整的需求全景，通常一屏或一页能够审阅，不为压缩篇幅省略关键条件。

| 全景包含什么 | 要能回答什么 |
| --- | --- |
| 问题与目标 | 为什么做，为谁做？ |
| 范围与非目标 | 本次承诺哪些行为？ |
| 核心场景与主流程 | 从触发到结果怎样发生？ |
| 关键规则与失败分支 | 什么必须成立，失败怎么办？ |
| 验收与未知项 | 怎样判断完成，哪里还不能确定？ |

全景不是目录，也不是提前堆满接口和字段。用一张主流程图和短规则表呈现行为；缺口标为待定，不能为了图看起来完整而编造答案。

**产物**：全景草稿。**继续条件**：整体方向得到明确认可，影响方向的缺口已有答案。细节可以待定，但要记录影响，不能将暂定内容写成正式承诺。

## 3. 演示场景

AI 按影响优先级选择场景。先展示正常路径，再补失败、边界和容易误读的反例。每轮一个主要决定，选项包含推荐前提与实际结果。

例如重复收藏是否更新时间：展示同一列表在两种选择下的顺序，并指出请求重试也可能改变时间。你判断行为；AI 将明确答案写入规则表，并更新全景。

| 问题 | 适合的表达 |
| --- | --- |
| 不同选择如何改变操作结果？ | HTML 场景演示 |
| 有哪些分支与返回路径？ | 流程图 |
| 哪些状态变化合法？ | 状态图 |
| 多个条件怎样决定结果？ | 决策表 |
| 多方如何交互与处理失败？ | 时序图 |

**产物**：已确认规则、对应场景与剩余问题。**继续条件**：核心场景的结果已经确认，未决细节的影响可界定。新答案改变方向时，返回全景重新确认。

## 4. 完善全文

AI 根据已确认场景组织章节，补充必要设计与验收。一次完善一个场景，但同步它对应的正文、图表、接口或数据约束和案例；不要先写完前几章，再让后续章节反向定义行为。

每条核心规则有稳定编号和确认状态。编号在修订中保持不变，被替代的内容进入历史记录。正文以可读规则为主，编号辅助追踪。

下面是收藏案例历史 v0.1 的关联表示例。提议尚未确认时，继续沿用该版本的规则；它不代表案例后续 v0.2 的当前约定。

| 编号 | 当前规则与状态 | 正文或设计位置 | 图表 | 验收 |
| --- | --- | --- | --- | --- |
| R-05 | 重复收藏保留原时间，已确认 | 重复操作、时间字段、接口处理 | 状态图 G-01 | AC-02、AC-09 |
| Q-01 | 重复收藏是否应置顶，待定提议 | 尚未写入当前规则 | 可提供候选演示 | 预期结果待确认 |

**产物**：不断完善的完整草稿与关联表。**继续条件**：必要规则有明确条件、结果、边界和验收；缺口显式记录。不要让未回答的问题消失在正文里。

## 5. 审校定稿

AI 依据全文解释正常、失败与边界案例，检查是否存在两种合理结果。检查来源是否支持事实，必要内容是否已经写入文档，图示、设计与验收是否沿用同一组规则。

实际渲染网页和图表，核对标题层级、表格、图注、窄屏与键盘操作。生成源码不等于展示正常，生成验收表不等于测试通过。

**产物**：完整 Spec、检查记录与剩余事项。**完成条件**：关键取舍由你确认，阻塞实施的未决事项已解决，全文和展示检查已完成；验收执行状态据实记录。

## 每轮的审阅页面

维护同一个页面或同一个可访问入口，复用版式。信息按以下顺序组织：

1. **整体概览**：目标、范围、主流程、当前版本和状态，保持容易找到。
2. **本轮讨论**：短结论、一个主要问题、具体场景与选项。
3. **完整草稿**：全文始终可访问，长解释与来源按需展开。
4. **修订记录**：变化、受影响位置、检查结果与待定事项。

页面用于帮助理解和反馈。静态页面的选择只改变预览；可以复制反馈回对话，由 AI 接收并记录。只有接入了真实提交与确认机制，才可显示“已提交”或“已确认”，不能用按钮视觉状态冒充保存结果。

工具不支持 HTML 时，使用同样顺序的短文本、表格和图表，说明网页尚未生成。长对话接续时，从当前版本、规则表、待定问题和下一步恢复，不依赖模型记住全部聊天。

## 每次修改的完整循环

**记录新决定 → 列出影响 → 同步修订 → 全文核对 → 更新版本。**

- 提议阶段保留当前基线，候选变化标为预览或待确认。
- 决定明确后，按规则编号和实际语义查找相关正文、示例、图表、设计与验收；关联表只是入口，不能代替全文检查。
- 发现新的关键取舍时，保留上一份完整基线，当前候选标为“正在修订”，先澄清依赖问题。
- 完成关联修订并核对旧规则残留后，更新完整草稿的版本与记录，不重排无关章节。

```text
当前基线：{版本与确认范围}
本轮变化：{旧约定 → 新约定及理由}
影响与实际修订：{正文、图表、设计、验收的位置}
检查：{已执行的检查及结果；未执行项明确标记}
待决定：{一个关键问题；没有则不强行提问}
完整草稿：{当前入口、版本和状态}
```

AI 的审校不能保证零遗漏。关键行为仍需由需求负责人按具体场景确认；检查记录应给出实际证据，而不是一句“已保持一致”。
